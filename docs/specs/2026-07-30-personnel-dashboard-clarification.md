# 人员看板 — 需求澄清文档

> 阶段：需求澄清（brainstorming 产出，自主决策假设，未经用户逐条确认）
> 日期：2026-07-30 ｜ 落盘：library-backend ｜ 配套：library-frontend

---

## 1. 需求

开发一个**人员信息管理面板**（非敏捷看板），承载两个业务域：

- **域 A 人员管理**：员工基本信息 CRUD + 批量导入。
- **域 B 成本预算**：按人员记录预算金额，带白名单可见性控制 + 批量导入。

> 原文：开发一个人员看板，有入口记录员工的基本信息以及增删改查，支持导入以及记录成本预算--白名单、批量导入。

## 2. 决策假设

| # | 歧义点 | 决策假设 |
|---|--------|----------|
| 1 | "看板"语义 | 信息管理面板（列表+详情+表单），非敏捷拖拽看板 |
| 2 | 员工字段 | 姓名、工号、部门、岗位、入职日期、手机、邮箱、在职状态 |
| 3 | 预算归集 | 按「人员 × 月份」记录预算金额 |
| 4 | 白名单 | 成本预算仅对白名单用户可见 |
| 5 | 导入格式 | Excel(.xlsx) 优先，CSV 兼容 |
| 6 | 批量导入 | 统一一个入口（与"支持导入"合并） |
| 7 | 工号 | 唯一；导入冲突跳过该行并报错 |
| 8 | 删除策略 | 人员逻辑删除（软删）；预算物理删除 |

## 3. 功能范围

### 人员管理
分页列表（按姓名/工号/部门/在职状态筛选）｜详情（含该人预算汇总）｜新增（工号唯一校验）｜编辑（工号不可改）｜逻辑删除｜批量导入（返回成功数+失败明细）

### 成本预算
列表（人员+月份维度）｜新增/编辑｜物理删除｜白名单鉴权（非白名单无入口）｜批量导入（工号/月份/金额）

### 明确不做
敏捷拖拽看板｜成本实际发生额核算｜部门树管理｜预算审批流｜SSO/组织架构同步

## 4. 数据模型

**Employee**：id(PK)、employee_no(唯一)、name(非空)、department、position、hire_date(date)、phone、email、status(0在职/1离职)、deleted(bool)、created_at/updated_at

**CostBudget**：id(PK)、employee_id(FK→Employee.id)、month(YYYY-MM)、amount(decimal(14,2))、created_at/updated_at；唯一索引(employee_id, month)

**CostBudgetWhitelist**：id(PK)、user_id、created_at

## 5. 接口契约（REST，仅新增向后兼容）

### 人员
`GET /api/employees` 分页查询｜`GET /api/employees/{id}` 详情｜`POST /api/employees` 新增｜`PUT /api/employees/{id}` 编辑｜`DELETE /api/employees/{id}` 逻辑删除｜`POST /api/employees/import` 批量导入

### 成本预算（白名单鉴权）
`GET /api/cost-budgets`｜`POST /api/cost-budgets`｜`PUT /api/cost-budgets/{id}`｜`DELETE /api/cost-budgets/{id}`｜`POST /api/cost-budgets/import`｜`GET|POST /api/cost-budgets/whitelist`｜`DELETE /api/cost-budgets/whitelist/{userId}`

### 导入响应
```json
{ "successCount": 48, "failureCount": 2,
  "failures": [{ "row": 3, "employeeNo": "E003", "reason": "工号已存在" }] }
```

## 6. 异常场景兜底

| 场景 | 兜底策略 |
|------|----------|
| 导入文件格式不支持/为空 | 整体拒绝，返回 400 + `文件为空或格式不支持`，不进入逐行解析 |
| 导入行数超限（>1000 行） | 整体拒绝，返回 400 + `单次导入上限 1000 行`，提示拆分 |
| 单行必填字段缺失（如工号/姓名空） | 跳过该行，记入 failures：`必填字段缺失` |
| 工号重复（库内已存在或文件内重复） | 跳过该行，记入 failures：`工号已存在` |
| 字段类型不合法（日期/金额/状态枚举） | 跳过该行，记入 failures：`字段格式错误` |
| 全部行失败（successCount=0） | 仍正常返回 200 + 完整 failures 明细，不抛 5xx |
| 预算金额越界（<0 或 >10^12） | 跳过该行，记入 failures：`预算金额超出范围` |
| 预算导入引用不存在工号 | 跳过该行，记入 failures：`工号不存在` |
| 非白名单用户访问成本预算 | 返回 403 + `无成本预算访问权限`，不泄露数据是否存在 |
| 操作逻辑删除人员 | 允许，预算关联仍按 employee_id 可读；人员列表默认过滤 deleted=true |
| 详情查不存在 id | 返回 404 + `员工不存在` |
| 并发编辑同一预算（同人员同月） | 唯一索引兜底，返回 409 + `该月份预算已存在` |
| 导入文件过大（>5MB） | 整体拒绝，返回 413 + `文件过大，上限 5MB` |
| 系统内部异常（DB/解析崩溃） | 返回 500 + `导入服务异常，请重试`，已入库数据不回滚（逐行独立入库） |

> 兜底原则：导入采用**逐行独立处理**——单行失败不影响其他行入库；整体级失败（格式/大小/超限）直接拒绝不进入解析。白名单鉴权失败统一返回 403 且不泄露资源存在性。

## 8. 对齐点

1. 前后端 REST 契约一致（字段名、分页参数、导入响应结构）。
2. 后端白名单鉴权，前端据白名单状态决定是否渲染预算入口。
3. 导入模板统一列定义（人员：工号/姓名/部门/岗位/入职日期/手机/邮箱/状态；预算：工号/月份/金额）。
